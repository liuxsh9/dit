## Overview

Add a `dit gc` CLI command and a server GC API endpoint that identify and remove unreachable objects from the object store. GC uses a mark-and-sweep approach: mark all objects reachable from any ref (branch, tag, staging index), then sweep objects not in the live set, subject to a grace period.

Additionally, fix the blob walker gap in `walk_commit_objects` that would cause blobs to always appear unreachable.

---

## 1. Bug Fix: Blob Walker Gap

### 1.1 Problem

`walker.py:_walk_tree()` only follows entries where `obj_type == "manifest"` or `"tree"`. Entries with `obj_type == "blob"` are silently skipped — their `obj_hash` is never added to any set. The result dict has no `"blobs"` key.

This means `walk_commit_objects()` returns an incomplete picture. GC built on top of it would delete all committed blob objects.

### 1.2 Fix

Modify `walk_commit_objects` and `_walk_tree` in `src/dit/core/walker.py`:

1. Add `"blobs": set()` to the result dict in `walk_commit_objects()`.
2. In `_walk_tree`, add a branch for `entry.obj_type == "blob"`:
   ```python
   elif entry.obj_type == "blob":
       result["blobs"].add(entry.obj_hash)
   ```

This is a backward-compatible change — existing callers that only use `commits`, `trees`, `manifests`, `rows`, `sidecars` keys are unaffected. The push command's delta logic (`new_objects = {obj_type: local - remote for obj_type in local}`) will automatically handle blobs once both sides include the key.

### 1.3 Impact on push

The push command in `main.py` uses `walk_commit_objects` to enumerate objects for upload. Currently blobs are walked for upload via `_clone_tree_objects` and `_fetch_tree_objects` (which manually handle blob entries), but `walk_commit_objects` is used for the push delta calculation. After this fix, blobs will also be included in the push delta, which is correct behavior. The `upload_order` list needs `"blobs"` added.

## 2. Core GC Module

### 2.1 New file: `src/dit/core/gc.py`

```python
@dataclass
class GCResult:
    live_counts: dict[str, int]      # objects in the keep set, by type
    deleted_counts: dict[str, int]   # objects deleted, by type
    total_scanned: int
    total_deleted: int
    tmp_deleted: int                 # stale tmp files deleted
    errors: list[str]                # any non-fatal errors


def collect_live_set(
    store: ObjectStore,
    ref_hashes: list[str],
    index_entries: dict[str, tuple[str, str]] | None = None,
) -> dict[str, set[str]]:
    """Mark phase: collect all reachable objects from refs + staging index.
    
    Args:
        store: object store to read from
        ref_hashes: list of commit hashes from all branches and tags
        index_entries: optional staging index {path: (hash, type)} — client only
    
    Returns dict with keys: commits, trees, manifests, rows, sidecars, blobs
    """


def sweep(
    store: ObjectStore,
    live_set: dict[str, set[str]],
    grace_seconds: int = 86400,
    dry_run: bool = False,
) -> GCResult:
    """Sweep phase: delete unreachable objects older than the grace period.
    
    Args:
        store: object store
        live_set: result of collect_live_set
        grace_seconds: only delete objects with mtime older than this many
                       seconds ago (default: 24 hours)
        dry_run: if True, count but don't delete
    
    Returns GCResult with counts.
    """


def gc(
    store: ObjectStore,
    ref_hashes: list[str],
    index_entries: dict[str, tuple[str, str]] | None = None,
    grace_seconds: int = 86400,
    dry_run: bool = False,
) -> GCResult:
    """Full GC: collect_live_set + sweep."""
```

### 2.2 Implementation details

**`collect_live_set`:**

1. Initialize `live: dict[str, set[str]]` with keys for all 6 object types.
2. For each `ref_hash` in `ref_hashes`: call `walk_commit_objects(store, ref_hash)`. Merge results into `live` (union).
3. If `index_entries` is provided (client-side GC):
   - For each `(path, (obj_hash, obj_type))`:
     - If `obj_type == "manifest"`: add `obj_hash` to `live["manifests"]`, load the manifest, add all `entry.row_hash` to `live["rows"]`.
     - If `obj_type == "blob"`: add `obj_hash` to `live["blobs"]`.
4. Return `live`.

**`sweep`:**

1. Compute `cutoff = time.time() - grace_seconds`.
2. For each object type in `["rows", "manifests", "sidecars", "blobs", "trees", "commits"]`:
   - Walk the filesystem: iterate `objects/{type}/` → 2-char dirs → 2-char dirs → hash files.
   - For each file: extract the hash from the filename. If hash is NOT in `live_set[type]`:
     - Check file mtime. If `mtime < cutoff`: delete (or count if dry_run).
     - Otherwise: skip (within grace period).
3. Clean `objects/tmp/`: iterate all files. If `mtime < cutoff`: delete.
4. Return `GCResult`.

**Filesystem iteration**: Use `Path.iterdir()` through the shard hierarchy. The store organizes as `objects/{type}/{hash[0:2]}/{hash[2:4]}/{hash}`.

**Grace period**: Default 24 hours. This protects objects written by in-flight operations (push, meta compute) that haven't yet updated their ref. The grace period must be longer than the maximum time between the first `store.write()` and the final ref CAS update in any operation.

**Dry run**: `--dry-run` counts candidates without deleting. Always safe to run.

### 2.3 What GC does NOT do

- **No compaction**: objects are individual files, not packed. No pack/repack concept.
- **No ref rewriting**: GC does not modify refs, commits, or any existing objects.
- **No server-side PR commit protection**: PR metadata may reference commits. If those branches are deleted and GC runs, the PR detail page may break. This is accepted — PRs referencing deleted branches is an edge case, and protecting them would require scanning the PR table as additional GC roots. Deferred.

## 3. CLI Command

### 3.1 `dit gc`

```
dit gc [--grace HOURS] [--dry-run] [--format table|json]
```

| Flag | Default | Description |
|------|---------|-------------|
| `--grace` | `24` | Grace period in hours — objects younger than this are never deleted |
| `--dry-run` | `False` | Count unreachable objects without deleting |
| `--format` | `table` | Output format |

### 3.3 Implementation

```python
@app.command()
def gc(
    grace: int = typer.Option(24, "--grace", help="Grace period in hours"),
    dry_run: bool = typer.Option(False, "--dry-run", help="Count without deleting"),
    format: str = typer.Option("table", "--format", help="Output format: table or json"),
):
```

The command:
1. Find repo root, build `ObjectStore`.
2. Enumerate all refs: `refs.list_branches()` + `refs.list_tags()` → collect all commit hashes.
3. Load staging index: `StagingIndex(dot / "index").entries_typed()` → `{path: (hash, type)}`.
4. Call `gc(store, ref_hashes, index_entries, grace_seconds=grace*3600, dry_run=dry_run)`.
5. Print result.

## 6. Orphan Audit Results

The explore agent identified these orphan-producing scenarios in the existing codebase. All are handled by the GC design (mark-and-sweep with grace period):

| Scenario | Orphan type | Protection |
|----------|-------------|------------|
| `dit add` without `dit commit` | Manifests + rows in staging | Index entries added to live set |
| `meta compute` CAS failure | Trees + commits + sidecars | Grace period (objects are fresh) |
| `merge --abort` after `dit add` | Manifests + rows from conflict resolution | Index cleared on abort → objects become orphans → swept by GC |
| Push CAS failure | Full commit chain on server | Grace period |
| Branch deletion | Full commit chain if sole ref | Swept by GC (correct behavior) |
| `dit fetch` without merge | Fetched commit chain | Swept by GC (correct behavior — fetch is advisory) |
| Process kill during write | Stale tmp files | tmp/ cleanup in sweep |
| Server resolve_conflicts CAS failure | Manifests + trees + commits | Grace period |

## 7. Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Algorithm | Mark-and-sweep | Simple, correct, no incremental state to maintain |
| Grace period | 24 hours default | Conservative; covers all in-flight operations. Configurable via `--grace` |
| Blob walker fix | Add to `walk_commit_objects` | Minimal change, fixes a real bug that would affect push too |
| Staging protection | Walk index → manifests → rows | Index is the only local reference to uncommitted objects |
| PR commit protection | Not included | Edge case — if users want browsable old PRs, they should keep the branch |
| Server auth | Admin only | GC is destructive; only admins should run it |
| Dry run | Always available | Safe to audit before deleting |
| Tmp cleanup | Included in sweep | Files older than grace period in `objects/tmp/` are certainly stale |
| Disk space reporting | Approximate (sum of file sizes deleted) | Exact freed space depends on filesystem block size; approximate is sufficient |

---

## 8. Out of Scope

- **Automatic/scheduled GC**: No cron-like background GC. Users run `dit gc` manually or via API.
- **Pack files / compaction**: Objects remain as individual files. No git-style packfile format.
- **Cross-repo GC**: Each repo's GC is independent.
- **PR commit pinning**: Protecting commits referenced by PRs. Deferred.
- **Ref log / reflog**: No undo mechanism for GC. Once deleted, objects are gone.
